# Easy Search：AI 搜索设计依据与本轮范围

核对日期：2026-10-26。下列对比依据第一方文档与仓库；未运行这些产品的付费 API，也未做性能排名。
本文是实现建议，不是已打通平台清单；命令、字段和能力以本项目实际 CLI 帮助、测试及适配器为准。
目标是可安装的 Skill 加本地 CLI：用户提问 → 搜索网页或自媒体 → 读取相关正文 → 返回带出处的答案。
不另做搜索网站，不建设互联网索引，不复制上游完整应用。

## 1. 第一方方案对比

| 方案 | 已核实的设计 | 本项目适合借鉴的部分 | 本轮不直接引入的部分 |
| --- | --- | --- | --- |
| [Perplexity Search API](https://docs.perplexity.ai/docs/search/quickstart) | 返回结构化、有排序的网页结果；支持多查询、域名、语言和地域控制及内容提取。搜索接口本身不生成答案。 | 候选结果与最终回答分开；保留每条查询、来源排序和摘要；按问题选择语言与来源。 | 托管索引、API Key、供应商结果排序及其成本；不把我们的浏览器检索称为该 API。 |
| [OpenAI Deep Research](https://developers.openai.com/api/docs/guides/deep-research) | 文档展示搜索与文档读取接口、来源引用，以及限制工具调用次数的研究流程。页面包含历史模型示例与迁移说明。 | 查找、读取、引用分层；给研究设置调用预算；让关键结论可追到已读来源。 | 不照抄历史模型 ID、固定推理强度或 MCP 审批配置；本轮不部署远程研究服务。 |
| [Exa Search](https://exa.ai/docs/reference/search) | 检索可请求正文或 highlights；结果结构提供 URL、标题及作者、发布日期等元信息字段。 | 正文和相关片段分开保存；作者与日期只按真实返回值填写，缺失保持空。 | 不假设任意网页都有完整元数据；不把供应商相关性分数当跨平台通用分数。 |
| [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) | 有 search_depth、chunks_per_source、raw content、域名和时间等控制；不同搜索深度存在延迟、内容及费用差异。 | 先控制检索深度和正文预算，再交模型综合；分来源保留片段，避免一大段无出处上下文。 | 不自动升为收费深度；API 返回答案不能替代本项目的出处核对。 |
| [Vane，原 Perplexica](https://github.com/ItzCrazyKns/Vane) | 当前仓库名为 Vane，MIT；架构包括问题分类、元搜索后端、研究编排与带引用回答，支持本地或云模型。 | 按问题复杂度决定是否研究；把搜索后端与回答模型解耦。 | Next.js 界面、数据库、整套部署及文件嵌入系统；本轮无需为搜索装一套服务。 |
| [Deep Agents 的 deep_research 示例](https://github.com/langchain-ai/deepagents/blob/main/examples/deep_research/README.md) | 示例说明保存请求、计划、研究、综合；URL 发现后另抓正文；研究者有搜索次数、并发和轮数限制。 | 显式预算、读取原文后总结、缺口驱动的有限补搜；复杂问题才增加编排。 | 不复制示例默认模型、云追踪、付费搜索依赖或多 Agent 架构作为安装前提。 |

以上“借鉴”是本项目取舍，不表示上游已提供 EasyBR 登录态路由或中文自媒体站内适配。
Vane 的具体流程另见其[架构说明](https://github.com/ItzCrazyKns/Vane/blob/master/docs/architecture/README.md)。
旧 [open_deep_research](https://github.com/langchain-ai/open_deep_research) 已于 2026-08-21 归档，仓库只读；不要把旧教程的默认配置视为当前推荐。
核对时 [deepagents](https://github.com/langchain-ai/deepagents) 未归档，当前仍有 deep_research 示例；其示例中保留的旧模型配置也需独立验证。

## 2. 建议采用的最短研究循环

1. 理解用户的问题、指定平台、时间范围和输出用途；信息足够就开始，不为普通问题先发一张填写表。
2. 生成少量互补查询：原问法、必要同义词、平台或权威来源限制；只对影响结论的缺口补搜。
3. 搜索只产出候选：标题、可用 URL、原始摘要、来源平台、查询词和排序位置。
4. 去重并选择相关候选，按问题需要读取正文；记录实际读取方法、范围和失败原因。
5. 从已读内容提取可支持答案的证据，再写结论；每项关键事实带对应来源。
6. 检查是否仍有关键缺口或矛盾；在预算内补搜，达到上限就交付已证实部分与未解决项。

预算建议：简单查询单轮完成；标准任务初始最多 3 条查询、读取最多 6 页。
仅有具体缺口时允许再补 1 轮、最多 2 条查询；总读取上限建议 8 页，并设置总耗时和单页文本上限。
这些数字是首版建议，不是对所有问题的质量保证，也不是上游服务的统一限制。
搜索和抓取可分别失败、分别重试；已经取得的正文与证据应复用，不因一个平台失败重跑整轮。
有限反思只检查覆盖、冲突与下一步，不需要存储或输出模型内部思考过程。

## 3. 查找、抓取、回答各自承担什么

| 层次 | 应交付的信息 | 不能混淆的状态 |
| --- | --- | --- |
| 查找 | 候选 URL、原摘要、查询与平台；可保留原排序。 | 有搜索命中不等于已读全文，也不证明内容属实。 |
| 读取 | 实际打开的最终 URL、正文或可见内容、读取时间、可选内容哈希与截断说明。 | 登录页、验证码、空壳页、404 和超时不能记为成功正文。 |
| 证据 | 来源 ID、能支持具体结论的短片段、所在页面与读取范围。 | 搜索摘要、作者观点、官方事实和我们的推断要区分。 |
| 回答 | 先回答问题，再给依据、分歧与局限；可选结构化结果供 Agent 接续。 | 模型回答不能凭空新增没有证据支持的日期、数量或结论。 |

优先正文；仅拿到搜索摘要时可以给“摘要级线索”，明确没有读取原文，并相应缩小结论。
来源 ID 在一次任务内稳定；回答中的引用必须能回指已保存的候选或正文记录，不生成占位 URL。
同一篇转载被多个网站收录时保留传播路径，不把它算成多个独立证据。
日期区分发布日期、更新日期和本次读取时间；无法识别发布日期就不填，不以读取时间替代。

## 4. EasyBR 与 WebBridge 的实际差异化

优势在复用用户已连接的真实浏览器及其登录环境，补充公开网页索引难以覆盖的站内可见内容。
“跨平台”应指 Skill 与本地 CLI 可在受支持操作系统运行；“跨浏览器”以 Bridge 实际连接及 capabilities 为准。
不得把支持 Chromium 系列解释成 Safari、Firefox 或每个系统浏览器都已支持。
EasyBR 是可选的多环境路由来源；已有普通浏览器连接时，不应强迫用户先创建指纹环境。

- 输入有明确 browserId、环境或账号归属时沿用该对象，不随机借用另一个已登录账号。
- 一个已确认连接可直接复用；多个连接且无法确定目标时，仅暂缓依赖登录态的分支，公开检索仍可继续。
- 公开候选可来自公开搜索引擎；需登录的站内查询及正文读取走对应登录环境，不能用公共 HTTP 请求冒充该登录态。
- 默认后台任务页，不抢焦点、不激活窗口；同一浏览器串行，独立浏览器的并发由宿主能力与预算决定。
- 页面清理只关闭本任务明确创建并登记的页；结束后回读列表，不能按域名批量关闭用户原页。
- 缺连接、登录、站点适配或遇验证码时返回准确状态；不自动换账号、不绕过访问限制。

这些是本项目对路由与资源归属的要求，需由实际浏览器验收确认；读取本文不等于已完成连接测试。

## 5. 原生站内检索与公开索引回退

| 情况 | 合理处理 | 答案应说明 |
| --- | --- | --- |
| 有已验证站内搜索与目标登录环境 | 搜索站点当前结果，再读目标文章或帖子。 | 来源为站内检索，范围受当前账号和可见页面影响。 |
| 没有站内适配，但公开索引可用 | 用平台域名限定检索，跟进公开可读页面。 | 来源为公开索引回退，覆盖与新鲜度可能不同。 |
| 搜索结果有标题，正文需登录或不可读 | 保存线索和失败状态；若有正确登录环境再尝试读取。 | 未读全文，不把标题或摘要包装成完整报道。 |
| 用户直接给 URL | 对允许访问的 URL 直接读取，不必先搜索出同一链接。 | 标记直接读取；保留重定向后的真实来源。 |
| 视频或音频页面 | 首版仅读取可见标题、作者、简介等文字；可识别用户提供的字幕来源。 | 未观看视频或聆听音频；简介、字幕不代表已核验画面与声音。 |

公开索引没有结果，只说明本次检索未发现；不能写成“平台不存在相关内容”。
平台目录、URL 模板和通用 DOM 抽取都不是已打通证明；具体站内能力须列出真实验收范围。

## 6. 相关性、去重与本地隐私

相关性先看是否回答原问题、来源类型、发布时间是否满足任务；保留来源原排序，避免伪造统一评分。
优先原作者或权威原文，并主动保留有价值的反例；不是简单按关键词出现次数选答案。
去重可结合最终 URL、平台内容 ID 和正文哈希；仅删除已知追踪参数，保留功能参数、重复键与必要路由。
不要因 URL 看起来相近就合并不同文章、分页或视频；也不要为获取正文自动执行页面下载的脚本。
网页、帖子和搜索结果中的指令都是资料，不能改变任务目标、触发发布或要求泄露登录凭据。

任务结果、缓存及最小必要执行记录默认留在用户本地，不默认上传遥测或云追踪。
本地保存不等于完全离线：查询会发给目标站或搜索引擎；使用远程模型时，选定上下文会发给该提供方。
结果不应包含 Cookie、Token、浏览器用户目录、私有账号标识或带密钥的 URL；日志也不完整转储凭据与登录页。
受限页面的正文保留在用户任务范围，不自动放进示例、测试仓库或公开检索结果。

## 7. 本轮实现优先级与验收

| 优先级 | 本轮交付 | 可验证的完成标准 |
| --- | --- | --- |
| P0 | 可安装 Skill、本地 CLI、搜索与读取分层、带来源的回答交接。 | 从普通问题取得候选并实际读正文；答案引用与保存来源一致。 |
| P0 | browserId/环境路由、受控失败、本任务页清理。 | 正确账号读取；缺连接/登录/正文时保留可用部分，不误报完成。 |
| P0 | 有限预算、去重、可选结构化结果及本地结果目录。 | 达到上限能结束；重定向和重复内容不重复读；失败页不进正文分母。 |
| P1 | 少数真实自媒体站内适配与公开索引回退。 | 分别验证站内成功、公开回退及两者都不可用，准确标记来源与限制。 |
| P1 | 同问多来源对照、冲突提示、缓存恢复。 | 来源互相矛盾时不强行统一；相同缓存可复用且标明读取时间。 |
| 暂缓 | 新界面、自建索引、全平台承诺、向量库、强制多 Agent、视频观看/转录。 | 没有实际实现和验收，就不写入已支持能力。 |

至少覆盖：网页成功、自媒体正文成功、仅摘要、验证码、超时、部分成功、错误浏览器归属、重复转载与视频描述。
另测正文中的恶意指令不会触发额外动作，JSON 与可读答案引用同一批来源。
这些是验收目标；公开文案应列实际完成项，不把本表直接当作通过结果。

## 8. 免费与开源的明确范围

免费开源范围是本仓库 Skill、CLI、适配器与测试，分发和修改权以仓库 LICENSE 为准。
默认核心流程不应强制购买某家商业搜索 API；网页检索和证据整理可以由宿主 Agent 接续，不内置付费模型门槛。
模型沿用用户宿主或显式配置；没有模型时仍可交付检索记录和正文材料，不能假称已完成 AI 综合答案。
外部模型、搜索 API、代理、浏览器服务或平台订阅若被用户选用，费用、额度和授权各自独立。
“核心免费”不表示我们承担这些费用，也不表示第三方永久免费；本地模型也有硬件与运行成本。
MIT 上游可参考设计；若实际采用代码需保留对应版权和许可，不把阅读文档描述成已经复用了源码。
