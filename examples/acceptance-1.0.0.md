# easybrSearch 1.0.0 上线准备与历史验收

首个正式上线版本从 **1.0.0** 开始，用户已完成本机试用并于 2026-10-26 授权提交发布。以下实搜数据采集于开发版 0.2.0 阶段，保留原始测量口径，不视为已上线的 1.0.0 性能基准。

2026-10-26，北京时间。优先范围：百度、Google、Bing、抖音、小红书。各点为本机当时的观察；网络、平台页面和登录状态变化会影响结果，不作为固定耗时保证。

## 五平台最终合并复测

相同查询为“AI动画”，每平台最多 3 条候选、仅搜索、单页预算 10 秒，最多四个浏览器组并行。同一浏览器内串行。

| 平台 | 实际状态 | 候选 | 本分支耗时 |
| --- | --- | ---: | ---: |
| Google | ok | 3 | 2.883 秒 |
| Bing | ok | 3 | 3.160 秒 |
| 百度 | ok | 1 | 4.027 秒 |
| 抖音 | result_load_timeout | 0 | 10.000 秒 |
| 小红书 | ok | 3 | 7.878 秒 |

首批候选 3.447 秒；整轮 19.125 秒，含等待和清理。四个分支取得候选，抖音该查询超时并写入人工处理入口。全部任务页清理回读通过。

小红书再按选定 ID 读取两篇帖子：2 条中 2 条正文成功，整轮 4.305 秒，无需重发搜索或临时浏览器脚本。

## 抖音的可用范围

另一条真实查询“Manim”返回 3 条可见视频卡片，分支 4.490 秒、整轮 4.935 秒，状态 `titles_only`。卡片有标题与摘要，链接指向真实搜索页；`contentURL: null`、`linkStatus: search_page_only`、`readStatus: link_unavailable`。没有把公开 DOM ID 拼成未验证的视频直链。

抖音加载存在波动：“AI动画”最终两次合并复测都未在预算内得到结果。因此本版将它定位为卡片线索与人工衔接，不能宣称稳定自动读视频详情。失败时，人工在原环境打开搜索页处理，其他平台结果照常交付。

## 固定样本优化前后

以下是开发过程中冻结的 0.1.0 与第一轮优化候选的同参数对照，每题每版 n=1。后续又做了平台与错误处理修复；表格不冒充最终发布版本的统计基准。

| 查询 | 原版总耗时 | 优化候选总耗时 | 正文读取 |
| --- | ---: | ---: | --- |
| AI 新闻 | 38.925 秒 | 19.485 秒 | 0 → 0 |
| Manim 入门 | 6.173 秒 | 4.561 秒 | 2 → 2 |
| LangGraph 文档 | 5.416 秒 | 2.800 秒 | 2 → 2 |
| B站＋CSDN | 4.644 秒 | 2.896 秒 | 2 → 2 |
| 抖音边界 | 6.655 秒 | 5.725 秒 | 0 → 0 |

新闻的两次自动选源均未读到正文，不能用耗时下降声称新闻查询已经成功。随后改用默认两阶段：当前宿主选出两篇新浪原始候选，再用固定 `read --from --ids` 命令，实读 2/2，读取阶段 1.618 秒。旧版那次“今日 AI 新闻”完整检索实际花了 76.756 秒，且自动阅读 3 次均失败；这正是取消临时补读、将正文适配和按 ID 读取固化的原因。

三引擎单独一轮“开源 AI 搜索 SearXNG Vane”：首结果 1.376 秒，整轮 2.170 秒，8 个候选，三个浏览器组并行。该观察与五平台合并查询不是同一工作量。

同一运行已保存的两份证据可直接复用，观察到约 2–3 毫秒的脚本处理、`browserCount=0`；保留原采集时间与正文 SHA，不能把复用当成刚刚重新查询。

## 返回与人工处理

- `--stream`：候选和读取状态逐条返回，最终 `done` 给摘要。
- `results.json`、`results.md`：最终结果；`sources/`：实际读到的文字证据。
- `partial-results.json`、`events.ndjson`：查询中可读的快照与进度。
- `handoff.json`、`attention`：登录、验证、超时、路由不可用或仅卡片的人工处理动作和实际页面入口。
- 原始签名与账号路由仅保存在本机私有文件中。

## 回归与独立复核

95 项离线测试通过（包含全局符号链接 CLI 入口回归）。覆盖平台范围替换、跨浏览器并行与同浏览器串行、流式先返回、正文选择、短说明、登录/验证状态、卡片无直链、查询参数归因、证据哈希与路径边界、账号路由延续、失败分支隔离及清理。

独立审核发现并修复四项可复现问题：来源 ID 路径越界、并行回调异常后的清理竞态、同路径不同功能参数的错误归因、单个失效路由中止其他有效平台。修复后均用原最小复现核验通过。独立宿主验收也完成了“搜索候选→选两条官方文档→读取→复用”的全流程。

所有列出的时间都是脚本墙钟时间，不含当前宿主 AI 筛选资料和组织答案的耗时。
